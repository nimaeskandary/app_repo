# wails3-react

This repo contains a Wails v3 sample app in a monorepo organized around deployable apps and shared packages.

## Project structure

```text
bin/                        # dev scripts
go.mod                      # single Go module for all Go code
package.json                # npm workspace root
cmd/                        # application entrypoints
pkg/                        # reusable packages
  greet/
    go/                     # Shared go greet package
      internal/             # Private to package, e.g. concrete interface implementations
storybook/                  # frontend component previews
```

## Dependencies

* go 1.26+
* node 26 - this can be upgraded if desired, this was just the LTS version when I installed node using nvm and I pinned it in `package.json`
* npm 11
* docker

## Setup

* run `npm install`
* Install [wails3](https://v3.wails.io/quick-start/installation/) as a global go tool via go install. Run through the setup wizard that will check if you have things like xcode, virtual devices, etc setup
* run `wails3 doctor` - this should say your system is ready

## Wails

[Wails3](https://v3.wails.io/quick-start/why-wails/) is used in this repo to build cross platform apps using go and react. This repo is generic and not every cmd executable needs to use wails, but wails is used to build targets such as `cmd/wordle`. 

`cmd/wordle` was bootstrapped with `wails3 init -n test-react -t react`. Some of the wails build files it came with was moved to `tools/wails` in an attempt to make things dry and reusable if another wails app is added to this project. 

### Common commands

* run dev mode on host, this will hot reload: `wails3 task -dir cmd/wordle dev`
* launch app on ios simulator: `wails3 task -dir cmd/wordle ios:run`
* build: `wails3 task -dir cmd/wordle build`
* re generate TypeScript bindings: `wails3 task -dir cmd/wordle common:generate:bindings`, e.g. autogenerated bindings in `cmd/wordle/frontend/bindings`
